topic: User Management adoption of the headless Access Control facade
updated: 2026-08-31
---

- (direction) Separate UM-owned package that answers um-integration-contract-request.md and specifies the ACCESS_CONTROL_PORT rebind, per-route mapping, projection boundary, and real-consumer HTTP E2E parked as a non-goal by spec-access-control-kernel-mvp. Touches services/backend only at code stages; no Access Control file, prisma schema, migration, or seed.
- (decision) The seam is the ACCESS_CONTROL_PORT binding in user-management.module.ts, not a route; behaviour is decided per feature string inside a new real adapter in src/user-management/infrastructure/ that injects AccessControlFacade forwards across the AD-2 boundary and replaces interim-access-control.adapter.ts wholesale (AD-21, no dual-running).
- (decision) isAllowed(userId, feature) delegates straight to AccessControlFacade.isAllowed; the three no-target features in use (user-management:create/deactivate/list) are exactly the ACM-1 seeded keys, so the position-string check is retired with no behaviour regression.
- (decision) READ_USER_FEATURE adopts now: allow self/reporting/pp, deny colleague as a two-state rule with the Profile Projection story recorded as the explicit trigger that flips it to allow-narrowed (§3.3.4). A denied whole-profile read is 403 recorded as a temporary consequence of the missing projection, never hardened as the intended convention.
- (open) No user-management:edit or photo permission is seeded, so the §2.2 dual gate for PATCH / PUT photo cannot be completed today. Two options recorded, (a) recommended (add the permission via a new Access Control kernel seed AD-1 sequence, adoption consumes it), (b) adopt READ only with a recorded interim write rule. Final call deferred to the human.
- (decision) The interim SESSION resolver is out of scope and retired by UM Epic 2; this package keeps it and uses the Bearer <token:<uuid>> seeded-UUID convention it already supports for Stage-2 fixtures.
